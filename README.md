School Management System (SMS) — Backend
Цей проєкт є бекенд-частиною CRM-системи для управління навчальним закладом. Написаний на Django 6.0 та Django REST Framework.

Система дозволяє автоматизувати облік студентів, груп, філій, розкладу занять, абонементів та відвідуваності з гнучким розмежуванням прав доступу на основі ролей (Адміністратор / Викладач).

-- Стек технологій --
Мова програмування: Python 3.13
Бекенд-фреймворк: Django 6.0 + Django REST Framework (DRF)
База даних: PostgreSQL 16 (з використанням persistent volumes для збереження даних)
Сервер застосунків: Gunicorn 22.0
Контейнеризація: Docker + Docker Compose
Автентифікація: JWT (Django REST Framework SimpleJWT) та Session Authentication

------

-- Швидкий запуск через Docker (Рекомендовано) --
Завдяки повній контейнеризації, вам не потрібно встановлювати Python, PostgreSQL чи залежності на свій комп'ютер. Увесь проєкт піднімається однією командою.

1. Клонуйте репозиторій та перейдіть у папку
git clone https://github.com/solomiabilyk/backend-it_step_sms.git
cd backend-it_step_sms

2. Створіть файл конфігурації оточення .env
Створіть файл з назвою .env у корені проєкту (поруч із docker-compose.yml) та скопіюйте туди наступні змінні:

DB_NAME=school_db
DB_USER=postgres
DB_PASSWORD=postgres
DB_HOST=db
DB_PORT=5432
SECRET_KEY=django-insecure-local-development-key-it-step-2026
DEBUG=True

3. Запустіть проєкт через Docker Compose
docker-compose up --build

Що відбудеться автоматично:
Окремо підніметься контейнер з базою даних PostgreSQL.
Бекенд-контейнер за допомогою скрипта entrypoint.sh дочекається повного запуску й готовності бази даних.
Автоматично виконаються всі міграції бази даних.
Запуститься production-ready сервер Gunicorn, який обслуговуватиме запити.
Проєкт буде доступний за адресою: http://localhost:8000

-- Запуск автоматичних тестів (Unit Tests) --
Уся ключова бізнес-логіка, права доступу користувачів (рольова модель) та ендпоінти повністю покриті тестами. Щоб запустити тести всередині працюючого Docker-контейнера, виконайте команду:

docker-compose exec web python manage.py test


-- Структура основних модулів проєкту --
users — Кастомна модель користувача (автентифікація за номером телефону phone, розподіл ролей: ADMIN, TEACHER).
branches — Управління філіями та локаціями школи.
subjects — Навчальні предмети (курси), прив'язані до філій.
students — База студентів, формування навчальних груп (Group) зі зв'язком Many-to-Many.
lessons — Генерація розкладу занять, прив'язка викладачів, груп або окремих студентів.
attendance — Журнал відвідуваності занять (статуси PRESENT, ABSENT, текстові нотатки).
subscriptions — Абонементи студентів (плани підписок, облік кількості занять та оплати).
